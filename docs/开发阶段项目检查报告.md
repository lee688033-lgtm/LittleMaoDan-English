## 6. 发现的问题

按严重程度排序。本轮按要求没有修改任何 UI、业务逻辑、依赖或架构。

1. **"我的"页面缺少设置入口（行为差异，不是崩溃）。** 页头副标题写着"学习记录与个人设置"，但"学习工具"分区只有一个单词本入口，没有深色模式、提醒或数据管理任何设置项。要么补设置页，要么改掉这句文案。当前深浅色靠系统 `values-night` 自动切换，所以"深色模式开关"这类项目前也无意义。

2. **单词详情页把词库 ID 当序号显示。** `WordScreen.kt` 显示"词库进度 1089 / 1495"。由于 1251-1255 断档，ID 1256 及以上的词序号会比真实位置大 5（`intuition` ID 1500 会显示"1500 / 1495"，分母大于分子）。这是踩坑日志已记录的遗留项，本轮仍未修改。

3. **代码里存在两座零引用孤岛。** `MaoDanIcons.kt`（STEP 2 自绘图标）与 `MaoDanIcon.kt` 在 Lucide 图标体系接入后已无外部引用。因为它们是未跟踪文件，删除不可恢复，所以本轮保留待你确认。`CET6Components.kt` 中的 `CET6SearchBar` / `CET6WordItem` / `CET6StatCard` 也只剩本页 Preview 在用，但清理它们要改动仍在服役的 UI 文件，按"不修改 UI"的要求本轮未动。

4. **`Scaffold-real.kt` / `Surface-real.kt` 处于未跟踪且未被忽略的状态。** 它们是 Apache-2.0 上游源码副本，`git add .` 会误提交。建议要么加入 `.gitignore`，要么移到忽略目录。

5. **上一轮自动化留下了 4.1 GB 的 `app/build/tmp-stage15-dumps/` 未清理。** 说明"临时产物写进 build 目录"的习惯缺少收尾步骤，`build/` 并不是无限安全的垃圾场。

6. **工作区有大量未提交成果。** 14 个已修改 + 31 个未跟踪文件，包含全部新词库 JSON、Lucide 图标、Liquid Glass 底部栏、答题卡模块。这些内容一旦误删无法找回，清理类任务的风险面明显变大。

7. **验证环境限制（非项目缺陷）。** adb 向输入框注入中文在当前输入法上不可靠，所以中文释义搜索只在 instrumentation 层断言（`直觉`→1500、`财政的`→626、`地下室`→936 均通过）；拼写"错误答案"分支本轮故意不点，避免往你的学习记录里写多余数据；像素级观感（卡片留白、玻璃胶囊高光、窄屏表现）未做主观验收，留给你人工确认。
